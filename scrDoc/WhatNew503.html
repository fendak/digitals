Див. Про оновлення 5.0

Оновлення модуля "Документація" до версії 5.03

1. У опції вибору категорії земель згідно містобудівної документації додано випадаючий список з функцією накопичення раніше введених значень:

Також тут діє запам'ятовування введеного значення з попереднього запуску скрипту для показу за замовчуванням при наступному запуску скрипту.

2. При формуванні документації стандартний скрипт автоматично запускає користувацький файл /TD/MyScript.txt (наприклад, для перевірки відповідності загальної площі сумі площ угідь). Оскільки тепер при запуску не другою, а третьою кнопкою перевірка відбувалася запізно, додано підтримку скрипту /TD/MyScriptGeneral.txt. Він запускається на самому початку, ще до запуску скриптів РТК, ДГМ, що дозволяє виявити помилку площі ще до генерації звітів РТК та ДГМ. Файл буде додано автоматично з наступним оновленням; ви можете використовувати його для будь-яких підготовчих дій з ділянкою.

3. Для документації виду 015 (зміна цільового) для трьох змінних, а саме форми власності, категорії і цільового, додано запам'ятовування раніше введеного значення:

Тут при зміні цільового раніше завжди підтягувало "приватна/100 землі с/г призначення /01.03 для ведення особистого селянського господарства" як найбільш типові значення. Тепер запам'ятовується раніше введене значення, але суто для виду документації 015. Для інших видів документації діють, як раніше, інші умови - для проєкту: форма власності - комунальна, цільове - землі запасу...(з кодом відповідно до категорії). Для проєкту по зміні угідь - значення підтягує існуючі. Нагадаю, що дане додаткове вікно появляється тільки для проєктів відведення і документації щодо інвентаризації.

4. На порохання користувачів, законодавчі акти для таблички обмежень скрипт тепер підтягує з XML (раніше підтягував з довідника Zakony.txt у папці Lists). Тепер, якщо робите кадастровий план із старого обмінника, на якому є обмеження, слідкуйте, щоб в обміннику були нові законодавчі акти. Наприклад, для ЛЕП замість Постанови від 04.03.1997 року Постанова від 27.12.2022 року. Варіант щоб підтягувало з обміника потрібний тому, що почали давати зауваження, що підстава обмежень не сходиться на кадастровому плані і в обміннику (а відтак у витягу з кадастру).

Серед іншого:
- виправленно змінну $AreaZahal: тепер вона працює для всіх видів документації (раніше була обмежена лише кодами 004, 006 та 020)
- виправлено змінну $Area, яка в груповому режимі в першій площі давала п'ятизначну цифру (додавала зайвий нуль).
- якщо включено збереження звіту в папку з обмінником, то при сортуванні скрипт тепер видаляє оригінальні сторінки з папки "Документація", залишаючи тільки папку "Сортування".
- забрано дефіси в описі суміжників за сторонами світу (з північного-заходу ⮕ з північного заходу)
